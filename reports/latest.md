## 評価指標

候補の正解は一つのツールに限らない。許容集合に入っていればそのツールは正解で、必須集合は必ず含めなければならない。質問すべきか、保留すべきかもラベルに含まれ、ユーザーが後から選んだ結果は精度に入れていない。

### 候補集合のF1

出したツールの集合が、出してよいツールの集合（許容集合）にどれだけ近いかを、依頼1件ごとに 0 から 1 で表した値である。表の数字は、その値を対象の依頼で平均したものである。150件全体の平均が総合の F1、種類ごとの平均がカテゴリ別の F1 である。

1件の計算は、次の二つを組み合わせる。

- 適合率は、出したツールのうち許容集合に入っていた割合である。余分なツールを足すと下がる。
- 再現率は、許容集合のうち出せていた割合である。出すべきツールを落とすと下がる。
- F1 は 2 × 適合率 × 再現率 ÷（適合率 + 再現率）である。どちらかが低いと、もう一方が高くても F1 は伸びない。

例は次のとおりである。

- 許容が疲労寿命予測だけで、それだけ出した。F1 は 1。
- 許容がはんだ亀裂進展とはんだ寿命予測の2件で、1件だけ出した。適合率は 1、再現率は 0.5、F1 は 0.667。
- 許容が1件で、その1件に加えて別のツールも出した。適合率は 0.5、再現率は 1、F1 は 0.667。
- 許容があるのに候補が空、または許容が空なのに候補を出した。F1 は 0。
- 許容も候補も空である。出さないのが正解で出していないので、F1 は 1。

F1 が見ているのはツールの集合だけである。質問の有無は、下の表の「追加質問の妥当」と「不要な質問」で集計する。

| 指標 | 意味 | 読み方 |
|---|---|---|
| 候補集合のF1 | 上の計算を依頼ごとに行い、平均する。1 に近いほど、出してよいツールに近い。 | 1 なら過不足なく一致。0.667 は、2件中1件だけ出すか、正解1件に余分を1件足した程度。 |
| 完全一致 | 予測集合が許容集合とまったく同じだった割合。 | 高いほど、過不足なく一致している。 |
| 必須の包含 | 必須ツールがすべて予測に入っていた割合。必須が空のケースは分母に入らない。 | 高いほど、落としてはいけないツールを残せている。 |
| 単一正解 | 正解が1ツールのケースで、その1件だけを選べた割合。 | 高いほど、目的が一つの依頼を選べている。 |
| 複数候補の妥当 | 複数候補が期待されるケースで、必須を含み、許容の範囲に収まり、2件以上出している割合。 | 高いほど、迷う依頼で候補を狭めすぎていない。 |
| 追加質問の妥当 | 質問すべきケースで、質問すると判断し、質問文もある割合。 | 高いほど、確認が必要な依頼で質問できている。 |
| 不要な質問 | 質問しなくてよいケースで、それでも質問した割合。 | 低いほど、明確な依頼を止めずに進める。 |
| 一つに決めた | 複数候補を残して質問すべきケースで、質問せず1件に決めた割合。 | 低いほど、書いていない目的で絞り込みすぎていない。 |
| 対象外の保留 | カタログ外、または適用が不明なケースで、候補を出さず保留した割合。 | 高いほど、カタログに無い依頼をツールに寄せていない。 |
| 処理エラー | 応答を候補に変換できなかった割合。選択の良し悪しではない。 | 0 なら、集計に乗らなかった応答はない。 |

カテゴリ別の値も同じ候補集合の F1 である。1件の依頼が複数カテゴリに入ることがある。誤り分類は規則による自動付与で、1件に複数の誤りが付く。人手で読み直した分類ではない。

## 示唆

目的が文面に書いてある依頼は、方式もモデルもほぼ解けている。差が出るのは、はんだ、振動、壊れそう、寿命のように対象だけが書かれ、知りたい量が決まっていない依頼である。この差を含めた総合では B1 が最もよい。採用の判断は冒頭の結論に書いた。

明確な入力の F1 は 0.940〜1.000、表層キーワードの引っかけは 6 件すべて 1.000、複数ツールを明示した依頼も 0.964〜1.000 である。カタログ上のツールの見分けは、目的が書いてあれば足りている。対象外の保留も 92.3%〜100% で、カタログ外を無理にツールへ寄せる失敗は小さい。

曖昧な入力の F1 は、B 0.778、Sol の直接選択 0.677、Luna の直接選択 0.654、Terra の直接選択 0.394、擬似jev は 0.233〜0.288 である。暗黙の前提でも同じ順に近く、Sol の直接選択 0.771 が最も高く、Terra の直接選択は 0.405 まで落ちる。総合 F1 の差は、この二種類の依頼でほとんど説明できる。

擬似jev は、答えが一つに決まる依頼では単一正解 98.1% と最も高い。複数候補を残すべき依頼では、複数候補の妥当さが 30.9%〜34.5% まで落ち、候補漏れが 35〜37 件ある。はんだのシミュレーションのように、質問は出すが候補集合を空にする。得点してからしきい値で切る手順は、単一の順位付けには向く。候補を並べて確認する手順には向いていない。同じモデルでも、直接選択の F1 は擬似jev より高い。Sol では 0.905 と 0.798、Luna では 0.890 と 0.772 である。Sol と Luna の直接選択の差 0.015 より、方式を変えたときの差の方が大きい。

辞書と規則の B は総合 F1 0.912 で最も高く、曖昧な入力と情報不足でも最も候補を残せている。一つに決めてしまった割合は 2.5% で最小、追加質問の妥当さは 97.7% で最大である。その代わり、質問が不要な依頼でも 10.9% は質問する。明確な入力の F1 0.940 は、LLM の直接選択より少し低い。B は候補を広げる側に寄っている。規則はカタログと仕様例から書いてあり、150 件の得点では調整していない。ただしラベルを付けた人と規則を書いた人は同じなので、曖昧な依頼で B が有利に出やすい。

直接選択の中では Sol が最もバランスがよい。F1 0.905、候補漏れ 16 件、一つに決めた割合 7.5%、対象外の保留 100% である。Luna は総合 F1 0.890 で近いが、一つに決めた割合が 17.5% と高く、意図の補完 8 件、質問不足 8 件がある。質問の出しすぎは 0 件なので、迷ったときに候補を狭めて進める。Terra は候補漏れ 33 件で、曖昧な入力と暗黙の前提に弱い。この課題の成績は、Terra、Sol、Luna という並びとは一致しない。

運用に落とすなら、依頼の書き方で分ける。目的が明示されているときは Sol か Luna の直接選択でよい。擬似jev でも明確な入力は解けるが、不要な質問が約 25% 残る。対象だけが書いてあるときは、B のように系統の候補を残して質問する。擬似jev と Terra の直接選択は、その役には使わない。同じ入力の繰り返しもないので、1 回の実行のばらつきは見ていない。

## 擬似jevが弱かった理由

採点モデルが、目的の書いていない依頼を低く点付けしたあと、後段の規則がその低い点を候補なしに変えている。明確な依頼では、3モデルとも目的が1つの49件をすべて一致させている。

採点の指示は、書いていない目的では点を上げず、目的が複数あり得るときはあり得るツールを同程度の点にして情報不足とすることである。後段は、最高点から15点以内でも50点未満のツールを候補から外す。50点以上が無ければ候補は空で、質問だけが残る。150件のうち、全部が50点未満になったのは Terra が67件、Sol と Luna が70件である。曖昧の印が付いた42件では、正解になり得るツールの最高点の中央値が40〜45点で、50点未満が26〜29件ある。モデルは曖昧な依頼を「まだ決められない」と採点し、後段はそれを「ツールが無い」と読んでいる。

## Terra の直接選択が弱かった理由

Terra は明確な依頼では候補を空にしたのが64件中2件である。曖昧の印が付いた42件では、候補を空にして質問だけにしたのが23件で、Sol は11件、Luna は10件である。複数の候補を出せたのは Terra が14件、Sol が26件、Luna が24件である。

「寿命を見たい」では、Terra ははんだ寿命か金属疲労かを質問している。「周波数を見たい」では、固有振動数か周波数応答かを質問している。質問の分かれ方は正解の二つに沿っている。候補欄は空である。Sol は同じ依頼で、その2つを候補に残してから質問している。この評価は候補の集合を採点するので、質問が正しくても候補が空だとその件は0点になる。Terra は書いていない目的でツール名を置くのを避けていて、その慎重さが減点になっている。

## B1 が質問する理由

B1 はモデルを使わない。質問は、次の規則が当たったときに出す。

1. 「意味」「文献」「日程」などの事務・説明の語があるときは、ツールを出さず質問する。
2. 「解析」「計算」「見たい」「したい」などの依頼の語が無いときは、ツールを出さず質問する。
3. 正式名・別名か、目的の手がかりが1件だけ一致したときは、質問しない。
4. それらが複数一致し、すべてが正式名・別名ではなく、「両方」「比較」などの語も無いときは、候補を残して質問する。
5. 目的の手がかりが無く、「はんだ」「振動」「壊れ」などの系統だけが一致したときは、その系統のツールを全部出して必ず質問する。この枝は「両方」を見ない。
6. 「亀裂」「寿命」などの弱い語だけが一致したときは、必ず質問する。
7. どれにも一致しないときは、ツールを出さず質問する。

不要な質問は、質問しなくてよい64件のうち7件（10.9%）である。内訳は、系統だけ一致した3件、名称か目的が複数一致した2件、依頼の語が無く保留した2件である。

系統の3件は、言い回しが目的の手がかりの文字列を含まない。「はんだフィレットの亀裂がどこまで進むか」は「亀裂進展」という連続した語を含まないので、目的の手がかりに当たらず、「はんだ」の系統で亀裂進展と寿命予測の両方を出して質問する。「両方をはんだで見たい」も同じ枝に落ちる。系統の枝は「両方」を見ないので、両方と書いてあっても質問する。

複数一致の2件は、短い語が別ツールに掛かる。「はんだ接合の熱疲労寿命」は寿命予測の手がかり「熱疲労寿命」に当たる一方、疲労寿命の別名「疲労寿命」が「熱疲労寿命」の中に含まれる。候補が2件になり、質問する。「破壊力学で金属母材のき裂進展リスク」は破壊力学の名称に当たる一方、「き裂進展」がはんだ亀裂進展の手がかりにも当たる。

依頼の語が無い2件は、「温度サイクルだからはんだ寿命で」と「固有値だけ見れば共振は分かるでしょ」である。ツール名は入っているが、「見たい」「計算」などの語が無く、中身を見る前に質問している。

## 辞書の充実さは B1 に効いている

効いている。ただし、別名を増やした量だけでは説明できない。曖昧な依頼で B1 が候補を残せているのは、ツールごとの別名が厚いからではなく、「はんだ」「振動」「壊れ」の語で、同じ系統のツールをまとめて出すからである。この系統はカタログの外、`config/method_b.yaml` にあり、ラベルを付けた人が規則も書いている。

目的の手がかりは各ツールで数語から十語弱で、言い回しが少し変わると外れる。外れると系統の枝に落ち、同じ系統のツールを全部出して必ず質問する。不要な質問7件のうち3件がこれである。手がかりや別名が短いと、別のツールの語の一部に一致して余分な候補が付き、複数候補の規則で質問する。7件のうち2件がこれである。辞書を厚くすると拾える依頼は増えるが、短い語を増やすと、明確な依頼で余分な候補と質問も増える。
